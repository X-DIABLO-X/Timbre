## 1. Purpose of This Documentation Package

This repository contains the complete, exhaustive, zero-ambiguity engineering specification for building a production-grade, real-time and offline expressive subtitle platform modeled after FCB Chicago and the Chicago Hearing Society's **[Caption with Intention©](https://www.captionwithintention.org/)**.

Every mathematical equation, threshold constant, neural network layer tap point, audio window stride, CSS custom property binding, JSON schema field, hardware profile, and file path has been explicitly pre-computed and documented. **A smaller code-generation model (such as Gemini Flash) or an autonomous multi-agent coding workflow can read these Markdown files and directly emit 100% of the production codebase without making architectural guesses or design assumptions.**

## 3. Recommended Traversal Order for Code Generation Models

When feeding this documentation package to a Flash model or coding agent, traverse the files in this exact sequence:

1. **Step 1 — Read Foundational Contracts First:**
   - Read [`00_overview/idea.md`](./00_overview/idea.md) and [`00_overview/architecture.md`](./00_overview/architecture.md) to understand the system invariants.
   - Read [`00_overview/folders.md`](./00_overview/folders.md) to lock in exact file paths and module imports.
   - Read [`01_contracts_and_schemas/caption_spec_schema.md`](./01_contracts_and_schemas/caption_spec_schema.md) and [`01_contracts_and_schemas/typography_and_math_constants.md`](./01_contracts_and_schemas/typography_and_math_constants.md) to generate the shared `CaptionSpec v2.0-cwi` types and mathematical mapping functions.
2. **Step 2 — Set Up Dependencies & Hardware Configs:**
   - Read [`02_tools_and_environment/tools.md`](./02_tools_and_environment/tools.md) and [`02_tools_and_environment/hardware_profiles.md`](./02_tools_and_environment/hardware_profiles.md) to generate `pyproject.toml`, `package.json`, and hardware auto-detection scripts.
3. **Step 3 — Execute Parallel Workstreams (Agents 1 to 4):**
   - **Agent 1 (Backend ML Engine):** Read [`03_models_and_weights/models.md`](./03_models_and_weights/models.md), [`04_pipelines/pipelines.md`](./04_pipelines/pipelines.md), and `04_pipelines/stream_0_*.md` through `stream_4_*.md` + [`06_optimizations/optimizations.md`](./06_optimizations/optimizations.md).
   - **Agent 2 (Custom Training & ONNX Export):** Read [`05_training_and_distillation/training.md`](./05_training_and_distillation/training.md) and [`05_training_and_distillation/datasets.md`](./05_training_and_distillation/datasets.md).
   - **Agent 3 (Chrome MV3 Extension & WebGPU Worker):** Read [`07_client_and_rendering/chrome_extension_mv3.md`](./07_client_and_rendering/chrome_extension_mv3.md) and [`06_optimizations/optimizations.md`](./06_optimizations/optimizations.md).
   - **Agent 4 (Frontend CwiRenderer, Shadow DOM & FFmpeg `.ass` Burn-In):** Read [`07_client_and_rendering/cwi_dom_renderer.md`](./07_client_and_rendering/cwi_dom_renderer.md), [`07_client_and_rendering/ffmpeg_ass_burnin.md`](./07_client_and_rendering/ffmpeg_ass_burnin.md), and [`07_client_and_rendering/wearable_spatial_haptics.md`](./07_client_and_rendering/wearable_spatial_haptics.md).
4. **Step 4 — Run the 256-Invariant Verification Suite:**
   - Read [`08_testing_and_verification/test_suite_256_invariants.md`](./08_testing_and_verification/test_suite_256_invariants.md) and [`09_flash_agent_prompts/flash_implementation_playbook.md`](./09_flash_agent_prompts/flash_implementation_playbook.md) to generate and execute all 256 unit tests.
